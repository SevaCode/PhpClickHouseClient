# ADR-0002: Версия 2.0 — ломающие изменения

- Статус: предложено
- Дата: 2026-11-13

## Контекст

Этапы 1–4 дорожной карты выполнены без нарушения совместимости ([ADR-0001](0001-backward-compatibility.md)).
Из-за этого рядом с новым API остаётся старое: два транспорта, мутабельный клиент, нетипизированные
сигнатуры, чтение через GET по умолчанию, устаревшие `HttpClient` и `Mode`.

Решение владельца:
1. Выпустить текущее состояние как **1.4.0**.
2. Сделать ветку `1.x` только для багфиксов.
3. Делать **2.0** в `master`.

Composer не обновит пользователей с `^1.x` до 2.0 сам, поэтому старые потребители не затронуты.

## Решение

Каждый пункт ниже владелец принимает или отклоняет отдельно. Реализуются только принятые
(колонка «Решение»). Рекомендация — мнение автора ADR.

| # | Изменение | Зачем | Миграция для пользователя | Рекомендация | Решение |
|---|---|---|---|---|---|
| 1 | Удалить `HttpClient` и `Mode` | Устарели давно, дублируют `ChcClient` | `HttpClient` → `ChcClient` | да | ? |
| 2 | Единственный транспорт — Symfony HttpClient; удалить `ChcHttpTransport` (`file_get_contents`) | Один путь кода; keep-alive, потоковое чтение, таймауты везде одинаковые | Нет, если не использовали транспорт напрямую | да | ? |
| 3 | `declare(strict_types=1)`, типы у всех параметров, возвращаемых значений и свойств | Ошибки ловятся статическим анализом и IDE | Передавать правильные типы (например, `int` вместо `'5'`) | да | ? |
| 4 | `ChcFormat` → `enum ChcFormat: string` | Опечатка в формате невозможна | `ChcFormat::JSON` не меняется; строки `'JSON'` → enum | да | ? |
| 5 | Иммутабельный клиент: `with*()` возвращают копию, `readOnly()`/`addSettings()`/`set*()` удаляются | Нет общего изменяемого состояния в DI и долгоживущих воркерах (RoadRunner, Swoole) | `$c->readOnly(false)` → `$c = $c->withReadOnly(false)` | да | ? |
| 6 | Чтение по умолчанию через POST + `readonly=2`, тело — `Content-Type: text/plain` | Нет лимита длины URL и SQL в access-логах; честный `Content-Type` | Нет (поведение сервера то же) | да | ? |
| 7 | `ping(): bool` без исключений (сливается с `isAlive()`) | Ожидаемое поведение, пример в README был неверным | Убрать `try/catch` вокруг `ping()` | да | ? |
| 8 | Иерархия исключений: `ChcServerException` (есть серверный код), `ChcConnectionException`, `ChcTimeoutExceededException`, `ChcMemoryLimitExceededException`; `getCode()` = серверный код или 0 | Различать ошибки сервера, сети и HTTP без разбора текста | `catch (ChcException)` работает; кто читал HTTP-статус из `getCode()` → `getHttpStatus()` | да | ? |
| 9 | `getJsonPool()` → `pool(array $queries): array<key, ChcResult>` вместо callback с 8 позиционными аргументами | Читаемо и типизировано | Переписать callback на чтение полей результата | да | ? |
| 10 | Минимум PHP 8.2 и Symfony `^6.4 \|\| ^7.0` | PHP 8.1 уже не поддерживается, Symfony 6.4 — LTS | Обновить PHP | да (или сразу 8.3) | ? |
| 11 | Переименовать классы без префикса `Chc` (`Client`, `Format`, …) | Префикс избыточен при наличии namespace | Переименования во всём коде пользователя | **нет**: дорогая миграция ради косметики | ? |

Не ломают совместимость, поэтому их можно сделать в любой версии без этого ADR:
- перевести комментарии на английский;
- PHP-CS-Fixer / PER-CS;
- повысить уровень PHPStan.

## Последствия

- 1.x получает только багфиксы в ветке `1.x`. Всё, что удаляется в 2.0, в 1.4 помечается `@deprecated`.
- [`UPGRADE-2.0.md`](../../UPGRADE-2.0.md) описывает миграцию по принятым пунктам.
- Высокоуровневый API, добавленный в 1.4 (`fetch*`, `iterate`, `insert`, `write`, параметры),
  в 2.0 сохраняется. Кто перешёл на него в 1.4, мигрирует минимально.
