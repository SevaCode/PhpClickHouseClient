# ADR-0003: Типизированные параметры запросов (`ChcParam`, `ChcType`)

- Статус: принято
- Дата: 2026-11-14

## Контекст

Параметры запросов передаются через плейсхолдеры ClickHouse `{name:Type}` и массив значений:

```php
$client->fetchAll(
    'SELECT * FROM events WHERE user_id = {id:UInt64} AND type IN {types:Array(String)}',
    ['id' => 42, 'types' => ['click', 'view']],
);
```

Тип и скобки приходится писать руками, а имя — дважды: в SQL и в ключе массива. Проверка на
ClickHouse 24.1 и latest показала:

| ошибка | результат |
|---|---|
| несбалансированные скобки в типе | Code 62 при выполнении |
| опечатка в типе | Code 50 при выполнении |
| плейсхолдер без значения | Code 456 при выполнении |
| значение без плейсхолдера | молча игнорируется |

Ограничения: значения никогда не подставляются в текст SQL; в 1.x изменение только добавляется
([ADR-0001](0001-backward-compatibility.md)); существующая запись `{name:Type}` продолжает работать.

## Рассмотренные варианты

1. **Проверка `{name:Type}` на клиенте** до отправки. Нужен лексер SQL (строки, идентификаторы,
   комментарии), а проверка «лишних ключей» ломает существующий код. Не принято.
2. **Короткая запись `{name}`**, тип берётся из `ChcParam` в массиве (`ChcSql::of()`), и клиент
   раскрывает её в `{name:Type}`. Требует того же лексера. Не принято.
3. **Вывод типа из PHP-значения.** Однозначен только для части случаев: `int` — это `Int64` или
   `UInt64`, пустой массив — `Array(?)`, `null` — `Nullable(?)`. Не принято.
4. **Позиционные `?` или `sprintf`-шаблон** (`ChcSql::format()`). Порядок аргументов легко
   перепутать, а именованных аргументов у `sprintf` нет. Не принято.
5. **Query builder.** Отдельная большая библиотека, которая быстро упирается в ограничения
   диалекта ClickHouse. Не принято.
6. **Stringable-объект параметра**, который сам выдаёт свой плейсхолдер при подстановке в строку.
   Предложено владельцем. **Принято.**

## Решение

- `ChcType` (`Stringable`) — тип ClickHouse, собранный фабриками с именами типов: `ChcType::UInt64()`,
  `ChcType::Array(ChcType::String())`, `ChcType::DateTime64(3, 'UTC')`, `ChcType::Map(...)`,
  `ChcType::Tuple(...)` и т. д. Для остальных типов есть `ChcType::of('...')` с проверкой непустоты
  и баланса скобок. Используется и отдельно, например `CAST(x AS $type)`.
- `ChcParam` (`Stringable`) — значение, тип и имя. `(string) $param` возвращает `{name:Type}`, значение
  уходит отдельно как `param_<name>`. Имя необязательно; по умолчанию генерируется `chc_N`,
  уникальное в пределах процесса.
- Именованные фабрики `ChcParam` повторяют фабрики `ChcType`: значение первым, затем аргументы типа,
  затем `?string $name`, затем `nullable: bool`:

  ```php
  $id    = ChcParam::UInt64(42);
  $types = ChcParam::Array(['click', 'view'], ChcType::String(), 'types');
  $name  = ChcParam::String(null, nullable: true); // то же, что ChcParam::Nullable(null, ChcType::String())

  $client->fetchAll("SELECT * FROM events WHERE user_id = $id AND type IN $types", [$id, $types]);
  ```

- Для массивов добавлены краткие фабрики `ChcParam::Array<Type>(array $value, ?string $name = null)`
  для простых скалярных типов без параметров: `Int8`–`Int256`, `UInt8`–`UInt256`, `Float32`,
  `Float64`, `Bool`, `String`, `UUID`, `Date`, `Date32`, `DateTime` без явно заданного часового пояса,
  `IPv4` и `IPv6`. Каждая эквивалентна
  `ChcParam::Array($value, ChcType::<Type>(), $name)`. Параметр типа остаётся явным, в том числе для
  пустого массива. Вариант `DateTime` с явно заданным часовым поясом, `DateTime64`, `Decimal`,
  `FixedString`, составные и nullable-комбинации не размножаются отдельными фабриками: для них остаётся
  общая `Array`.

  Общая форма — `ChcParam::of($value, ChcType|string $type, ?string $name)`.
- `ChcParam` передаётся в массиве параметров списком или под ключом, совпадающим с его именем.
  Можно смешивать с обычными `'name' => value`.
- До отправки запроса бросается `InvalidArgumentException`, если:
  - плейсхолдера `ChcParam` нет в SQL (поиск точной строки `{name:Type}`, без разбора SQL);
  - ключ массива не совпадает с именем объекта или имя повторяется;
  - `ChcParam`/`ChcType` вложен в значение другого параметра;
  - в скалярную фабрику передан `null` без `nullable: true`.
- Тип и фабрика — разные классы: `ChcType::UInt64(42)` не сделан, потому что тогда один метод
  возвращал бы то тип, то параметр, `null` нельзя было бы отличить от отсутствия значения, а в
  `ChcType::DateTime64(3)` был бы неясен смысл аргумента.
- Тип не превращается в `Nullable` автоматически при значении `null`: тип плейсхолдера не должен
  зависеть от данных.
- `ChcParam::Tuple` не добавлен: кодировщик превращает PHP-список в массив `[...]`, а не в кортеж.

## Последствия

- Опечатки в типах и скобках исключены по построению; имя пишется один раз; неиспользованный
  `ChcParam` обнаруживается до запроса. Безопасность прежняя: в SQL попадают только имя и тип.
- Обычные параметры `['id' => 42]` работают как раньше и с SQL не сверяются, поэтому изменение
  обратно совместимо и выходит в 1.x (следующий minor) и 2.x.
- Значение без плейсхолдера по-прежнему молча игнорируется для обычных параметров; плейсхолдер без
  значения по-прежнему ловит сервер (Code 456).
- Автоимена `chc_N` видны в логах запросов; для читаемых логов имя можно задать явно.
- Поиск подстроки не учитывает литералы и комментарии: плейсхолдер, встречающийся только внутри
  строки или комментария, считается использованным.

## Кодирование числовых массивов в 1.4

В типизированных массивах, в том числе вложенных и с элементами `Nullable`, строки для
`Int*`, `UInt*` и `Decimal(precision, scale)` отправляются без кавычек, если число
точно представимо объявленным типом. Диапазон проверяется без преобразования в PHP `int`
или `float`: иначе ClickHouse может переполнить целое или отбросить часть десятичной дроби.
Остальные строки остаются в кавычках. Проверка не добавляет исключений при создании
`ChcParam` и не меняет кодирование обычных параметров.
